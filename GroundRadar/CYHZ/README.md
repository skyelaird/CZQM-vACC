# CYHZ Test Package — Ground Radar Plugin

Generated by `tools/osm-to-grp/extract.py` from the config at `tools/osm-to-grp/config/cyhz.yaml`. This folder contains everything CYHZ-specific the GR plugin needs to load a working ground / tower view.

## Package contents

| File | Purpose | Size |
|---|---|---|
| `GRpluginMaps.txt` | Map block definitions (surface, runways, stop bars, helipads, labels). Most surface fills come from the AeroNav `.sct` via `SCTFILEDATA:` references. | ~23 KB |
| `GRpluginSettings.txt` | `[CYHZ]` settings block: `Airport_Refpoint`, four runway thresholds, SMR mode, safety-net flags, APM approach-path definitions for all four runway ends. | ~1.3 KB |
| `GRpluginStands.txt` | 40 `STAND:` entries with per-stand radius (ICAO ARC category) and heading. For occupancy detection only — auto-assignment is disabled via `System_AutoAssignDist=0`. | ~3.1 KB |
| `asr/CYHZ_Ground.asr` | Ground controller ASR. `GroundMode:CYHZ`, `AirportRadius:1.3`, tight WINDOWAREA over the apron and runways, 18° display rotation, `TopSky_QM` tag family, Virtual Controller Assistant params. | ~1.1 KB |
| `asr/CYHZ_Tower.asr` | Tower controller ASR. `TowerMode:CYHZ`, same radius, wider WINDOWAREA (~10 nm around ARP, sized for the CYHZ Control Zone). | ~1.1 KB |
| `CYHZ-TWR_GRP.asr` | **Pre-rebuild ASR** — preserved for reference / fallback. Not part of the test package. Uses sector-file `Geo:` / `Regions:` directly rather than GRP MAP blocks. |

Subordinate documentation (not loaded by the plugin):
- `docs/developer-notes.md` — maintainer notes
- `docs/lppt-analysis.md` — Phase 1 LPPT reference analysis (has known errors flagged in the GRP capability analysis)

## Prerequisites

- **Ground Radar Plugin 1.6** installed in EuroScope, with shared data files (`GRplugin.dll`, `ICAO_Aircraft.json`, `ICAO_Airlines.txt`, `GRpluginSymbols.txt` — the last one is optional; defaults are fine).
- **AeroNav AIRAC sector file** at the path referenced by `SCTFILEPATH:` in `GRpluginMaps.txt`. The generator emits an absolute path pointing at `..\reference docs\CZQQ-CZQM-CZQX_*.sct` in this repo (wildcard-matched). For local testing this works as long as the file is present. Edit `SCTFILEPATH:` if you keep the `.sct` elsewhere.
- **TopSky plugin** loaded (the ASR's `PLUGIN:TopSky plugin:NoDraw:1` line suppresses TopSky overlay drawing on the GR display). If you don't run TopSky, the line is a no-op.

## Install steps

Two paths depending on whether you're integrating into an existing GR setup or running a standalone test.

### A. Standalone test (recommended for first look)

1. Pick a folder to act as the GR plugin's working directory (e.g. `D:\GRtest\`).
2. Copy `GRplugin.dll`, `ICAO_Aircraft.json`, `ICAO_Airlines.txt` from your existing GR install (or from `..\reference docs\portugal\GroundRadar\` in this repo as a starter set).
3. Copy the four generated files from this folder:
   - `GRpluginMaps.txt`
   - `GRpluginSettings.txt`
   - `GRpluginStands.txt`
   - `asr\CYHZ_Ground.asr` and `asr\CYHZ_Tower.asr` (keep the `asr\` subfolder or put them next to the rest, EuroScope finds them either way)
4. In EuroScope: load the GR plugin pointing at this folder, then open `CYHZ_Ground.asr`.

### B. Integrate into your existing GR install

If you already have a GR plugin install with `[other_icao]` settings blocks and an existing `GRpluginMaps.txt` with maps for other airports:

1. **Backup** your existing `GRpluginMaps.txt`, `GRpluginSettings.txt`, `GRpluginStands.txt`.
2. **`GRpluginMaps.txt`** — our file contains everything CYHZ. If your existing file has CYHZ content, replace; if it has other airports too, append our content to your existing file (or merge by hand). The `COLORDEF` block at the top needs no conflict resolution unless you use the same names.
3. **`GRpluginSettings.txt`** — copy the `[CYHZ]` block (and the `AppPath=` lines below it) into your existing file. Replace any prior `[CYHZ]` section.
4. **`GRpluginStands.txt`** — append our 40 `STAND:` (with `HEADING:`) entries to your existing file. They are namespaced by `CYHZ:` so they shouldn't clash with other airports.
5. **ASRs** — drop `CYHZ_Ground.asr` and `CYHZ_Tower.asr` into your ASR directory.

## Smoke-test checklist

After installing, with the AIRAC sector file loaded and at least one sweatbox aircraft on the field:

1. **Load `CYHZ_Ground.asr`.** Expect: GR display centred on the apron, surface visible.
2. **Verify surface rendering** comes from the `.sct`:
   - Grass should be dark green
   - Apron should be mid-grey (lighter than runways)
   - Runways should be dark grey
   - Helipads visible (south of Terminal 2)
   - Buildings (hangars, terminal, tower) visible
3. **Check labels**: stand numbers visible at parking positions; taxiway letters at correct taxiway intersections.
4. **Toggle the Map Selection Window** (Global Menu → Functions → Map Selection) — should see folders:
   - `CYHZ` (containing SURFACE, LINEWORK, PARKING DETAIL, APRON CARGO, BUILDINGS, HELIPAD, HELIPAD LABEL, STAND NUMBER, TAXIWAY NAME, RUNWAY ARROWS, LVP OVERLAY)
   - `CYHZ STOP BARS` (containing STOP BARS 05/23 and STOP BARS 14/32 — only one set visible at a time based on active runway)
   - `CYHZ TWY DATA` (13 hidden taxiway-tag blocks; not shown in menu unless you reveal hidden items)
   - `DIV` (BACKGROUND)
5. **Set active runways** in EuroScope's runway config (e.g. all 05/23 → arr+dep). Expect:
   - `MAP:RUNWAY ARROWS` shows blue arrows along 05 (departures) or yellow on 23 (arrivals), or mixed if both
   - `MAP:STOP BARS 05/23` becomes visible; `STOP BARS 14/32` hides
6. **Park a sweatbox plane within ~20 m of a stand** (e.g. gate 14):
   - Stands List window (Global Menu → Lists → Stands) shows the gate as occupied (under PARKED column)
   - Raw video aircraft silhouette appears at the stand (Pierre Ferran shape; `Airport_SMR_Raw=2` is set)
7. **Trigger a safety net**: set a sweatbox plane's transponder to 7500 → ECM should fire (HIJACK alert in Alerts List + on track label).
8. **Toggle LVP** on the Global Menu (left-click the LVP/NORMAL indicator). Expect:
   - `MAP:LVP OVERLAY` becomes visible (low-visibility variant linework from the `.sct`)
   - The RWY area widens per `System_RwyArea_LVP=90.0` (only relevant for the safety net's runway zone calculations)
9. **Load `CYHZ_Tower.asr`**. Expect: wider view extending ~10 nm around the airport, tower-mode label layout, no stand assignment menu.

## Known limitations / things to watch

- **F-class stand categories overstated.** The GSX profile rated stands 22, 24, 27 as F (≥65 m wingspan). Real CYHZ ops don't see A380s — these are probably D/E in practice. Override in `tools/osm-to-grp/config/cyhz.yaml` under `stand_categories:` and re-run `extract.py` if you want to downgrade them.
- **6 stands with no heading.** Gate nodes without an associated `parking_position` way and not in the GSX profile (`4`, `10`, `26`, `34`, `40`, `44`) get no `HEADING:` line. Occupancy still detects, just without orientation constraint. Adding entries to `stand_headings:` in the config fixes them if needed.
- **Taxiway type/restriction blocks are no-ops.** The hidden `CYHZ TWY DATA` folder contains `TWYTYPE:NONE` polygons per named taxiway. Without `RESTRICTION:` lines they tag the geometry but enforce nothing. CYHZ publishes no taxiway aircraft-type restrictions today; scaffolding stays in place for future use.
- **`SCTFILEPATH:` is an absolute path** to this repo's reference `.sct`. For production distribution it should become a relative path (e.g., `..\Sector\CZQQ-CZQM-CZQX_*.sct`) once we settle on the package layout.
- **Light/dark palette switching deferred** to Phase 4 of the rebuild spec. One palette only for now (dark, LPPT-inspired).
- **Tag families** are the existing `TopSky_QM`. Per-mode customisation (spec §5) is Phase 5 work.

## Regeneration

To regenerate any of the four output files after editing the config:

```powershell
cd D:\GitHub\CZQM-vACC\GroundRadar\tools\osm-to-grp
python extract.py config/cyhz.yaml
```

The tool fetches OSM data on first run (cached at `tools/osm-to-grp/data/cyhz_raw.json`) and re-uses the cache thereafter. Pass `--refresh` to force a re-fetch.

## Reporting back

Loading-in issues to look for and call out:
- Any plugin chat-tab errors ("GRplugin" tab) at load time
- Map blocks that don't render (probable `SCTFILEPATH:` mismatch or sector-file group-name mismatch)
- Stand circles drawn in the wrong places (per-stand position issue — OSM placement may need overrides)
- Safety nets that don't fire when expected (settings tuning needed)
- Visual artifacts (colour clashes, layer ordering issues, label collisions)

Reporting these back lets the next iteration of the config / tool catch them.
